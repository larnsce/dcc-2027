# Session plan for the DCC 2027 workshop

Planning notes for the 50 minute slot. Not part of the submission.

| Time | Block | What happens |
|----|----|----|
| 0:00 to 0:05 | Why we publish for humans | The five year workflow in one picture, the three stages of data (raw, analysis ready, final), and what the room will see |
| 0:05 to 0:28 | Live run, part 1 | Raw dataset to a washr data package. The agent does the mechanical steps (folder structure, data dictionary, metadata, README). Participants send proposed changes from their phones (channel to decide: Element, WhatsApp, or a QR comment form), and the changes are merged live |
| 0:28 to 0:36 | Live run, part 2 | Release, DOI, website. pkgreview is named as the review step, not run. The disclosure trail (commit trailers, prompts archive) shown on the repository |
| 0:36 to 0:46 | Open questions | Publishers selling AI curation, disclosure, sensitive data, rewards moving to data. Short discussion per question |
| 0:46 to 0:50 | Take home | Where the repository lives, how to run washr on your own data, who to ask |

## Open decisions

- Participation channel. Participants propose documentation changes from their phones and the changes are merged live. Options: Element, WhatsApp, or a QR code to a comment form (Supabase). The technical detail stays out of the abstract.
- Pre-workshop setup. Asked the organisers in the submission email whether participants can be asked to prepare, e.g. a GitHub account, and R with washr installed for those who want to run the tools themselves.
- Tools shown. washr is run live. pkgreview is named as the review step, not run.
- Framing. Closer to an interactive pitch or keynote than a training workshop. The workshop slot fits.
